Raid 是一款面向论文、教材和技术文档的轻量、可扩展 AI 阅读器。它将多文件组织、连续阅读、精确选区、OCR、批注、文档标签、基于检索的 AI 对话和用户自定义模型集中在一个克制的桌面工作区中。

> 作者：**xyLee** · [项目仓库](https://github.com/lxymol/Reading-Assistant)

## 主要功能

- 支持 PDF、图片、纯文本、Markdown、源码、EPUB 和常见办公文档，通过直接渲染或本地转换为 PDF 阅读
- 可通过文件选择器、拖放或剪贴板一次导入多个文件
- 文件可以保持未分组，也可以放入轻量、可排序的组合中
- 对话归属于发起对话的文件，同时支持对选区、对全文和对组合三种 AI 范围
- 可选择原生文字或任意数量的跨页视觉区域，并使用 OCR 与可选视觉模型
- 支持彩色文字高亮、矢量墨迹批注，以及可拖动、可命名的文档标签
- AI 引用可跳转至对应文件、页码和精确区域
- 工具栏可停靠在左右两侧，也可拆为浮动窗口
- 可连接 OpenAI 兼容 API 或本机已登录的 Codex 账户，并分别设置默认、视觉和推理模型
- 支持导入 Skill 与语言包，以及可选用户记忆

## 文件组织

Raid 中的组合只是一个有序文件集合。未分组文件以简洁列表放在所有组合下方；组合本身可以排序，文件也可以直接拖入其他组合，无需重新导入。

对话归属于创建它时所在的文件，并折叠显示在该文件下方。对话仍可使用组合上下文；分解组合只会把文件移到未分组区域，不会删除原有“对组合”对话。

## AI 上下文策略

Raid 将问题、选区和文档作为正常对话输入，不自动添加论文助教角色或强制分析步骤：

- **对选区：**发送当前经过编辑的选区文字；存在视觉模型时，同时发送当前视觉选区原图。每轮默认携带选区对话上下文，发送后选区图片转入对应的用户消息，点击缩略图可按需查看原图。
- **对全文：**提供当前文件的完整可读文本。Codex 模式按需读取完整附件，不再只提供检索段落；文本文件保留原始 UTF-8 内容，PDF 使用提取出的文字和页码。扫描件需要 OCR，图表可用视觉选区补充。
- **对组合：**逐个导出组合中的完整文本文件，让模型自行读取和比较；附件按 ID 访问，文件正文不会全部常驻前端内存。
- **API 模式：**发送完整文本，单次最多 300,000 字符；超过预算明确报错并建议使用 Codex 或拆分文件，不截断正文冒充全文。
- **引用：**全文模式仍提供可点击的引用定位；模型可以使用完整附件中的其他内容，不受检索片段限制。
- **批注：**可见墨迹会合成进视觉选区，相关文字批注会加入提取上下文；重叠高亮会被归一化，避免同一文字出现多层重复高亮。

选区 OCR 只是可编辑的辅助信息，并不是唯一证据路径。只要视觉选区仍在，Raid 可以把识别文字和原图一起发送，让模型核对 OCR 无法精确还原的字符。

### Codex 工具调用

Raid 通过 [Codex App Server](https://learn.chatgpt.com/docs/app-server) 复用本机 Codex 的模型和持久会话；模型设置留空时跟随 Codex 默认模型。只显示最终回答，隐藏推理和过程性消息；Skill 仅在用户明确选择时应用。历史选区图片按请求预算恢复，已成功恢复的原生线程沿用自己的多模态历史。

本地命令、任意路径图片读取、外部 MCP 和插件文件入口关闭。模型通过 `read_attachment` 和 `search_attachments` 查阅用户提供的完整附件，每次读取最多约 32 KB；请求生成文本文件时，通过 `create_text_file` 写入临时目录，原始文件随后进入文件栏。请求完成或取消时清理附件副本和工具路由，Codex 子进程空闲 90 秒后退出。旧会话保留 Raid 中的历史，在首次提问时迁移到新的附件工具会话。

模型、推理配置、可用工具和上下文会影响回答；接入原生会话不能保证与 ChatGPT 产品逐字相同或每次都正确。

## 大型文档与内存策略

- PDF 页面靠近阅读位置并短暂停留后才渲染；快速翻页经过的页面保留占位。远处页面释放画布和 PDF.js 页面资源。
- 当前页和附近页拥有更高渲染优先级。OCR 只在选区或明确需要文字时启动，空闲一段时间后自动结束工作线程。
- 切换文件时销毁上一份 PDF 的加载任务，并回收临时对象 URL。
- 非活动组合在内存中只保留轻量摘要；完整文件元数据、对话和索引会在再次打开时从本地恢复。
- 对话选区原图单独持久化；未打开的对话不加载图片，删除消息、对话或其所属文件时删除对应图片。
- 长对话先显示最近 40 条消息，较早消息按需加载；离开视口的缩略图会释放。单次视觉请求限制为 8 张、合计 12 MB。
- Windows 桌面端使用软件合成，避免 Chromium GPU 进程在反复滚动 PDF 时持续积累纹理内存。

这些策略让正常内存占用围绕当前阅读内容变化，而不是随文库总文件数或 PDF 总页数持续增长。
`npm run test:memory` 会在隐藏桌面窗口中打开 120 页 PDF、反复滚动六轮，验证阅读进程组工作集低于 500 MB 且没有持续增长，并核对启动 Codex 后的私有提交内存。逐进程工作集相加会重复计算共享页面，因此测试同时报告两种数值。500 MB 阈值适用于该测试场景；实际生成任务、超大文件和其他机器环境仍需分别实测。

## 本地存储

程序旁 `RaidData/Data/projects` 中的版本化记录会保存导入源文件、对话、阅读位置、高亮、批注、标签和本地文档索引。旧版 IndexedDB 项目会自动迁移。在“设置 → 记忆 → 项目记忆”中删除组合，会永久删除对应记录与资源。

用户记忆是另一层可选、可编辑的稳定背景和回答偏好画像；文档原文不会被学习进用户画像。

## 安装

Windows 用户可从 [GitHub Releases](https://github.com/lxymol/Reading-Assistant/releases) 下载安装程序。Raid 不修改系统环境变量，也不要求另行安装 Node.js。

当前版本：`2.2.0`。

## AI 配置

打开“设置 → 模型”，可选择 OpenAI 兼容 API，或复用电脑上已经登录的 Codex 账户。API 模式使用自定义接口和 Key；Codex 模式从本机 Codex 登录状态获取模型。两种接入方式均采用流式输出。

| 配置 | 用途 |
| --- | --- |
| 默认模型 | 文字处理、全文与组合问答、翻译、Skill 路由和可选用户记忆更新 |
| 视觉模型 | 视觉选区、公式、图表、示意图、扫描内容与 OCR 核对 |
| 深度思考模型 | 开启深度思考后的纯文字推理任务 |

高级配置留空时会沿用默认接口和 Key。兼容接口应提供 `GET /models` 与 `POST /chat/completions`。

## Skill 与语言包

- 在“设置 → 技能设置”中导入根目录包含 `SKILL.md` 的文件夹，Raid 会读取其说明和支持的文字参考文件。
- AI 可根据 Skill 元数据自动路由，也可在消息开头输入 `/skill-command` 强制指定。
- 在“设置 → 语言设置”中导入包含 `language.json` 的文件夹；所选语言同时控制界面、AI 回答和翻译目标语言。

## 从源码运行

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

启动隔离的桌面测试版：

```bash
npm run desktop:test
```

## 构建

```bash
npm run lint
npm test
npm run build
npm run test:memory
npm run desktop:pack
```

Windows 安装包会生成到 `release-2.2.0`。

## 隐私与安全

- PDF 渲染、文字提取、OCR、索引、批注、标签和项目存储都在本机完成。
- 只有发起 AI 操作后，用户配置的 AI 服务才会收到材料；具体内容取决于上文所述的处理范围。
- 导入文件及相关资源保存在 `RaidData/Data/projects`，除非内容被包含在 AI 请求中，否则不会上传。
- API 配置保存在应用本机数据目录，不会进入仓库或安装包，但并非操作系统密钥库加密。

安全问题请参阅 [SECURITY.md](SECURITY.md)。
